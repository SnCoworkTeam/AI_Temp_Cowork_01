# 镜像已 load、代码已拉取到服务器 — 接下来怎么做

## 一、这两个文件放哪里？

**`docker-compose.opencode.yml`** 和 **`.env.example`** 必须和本说明放在**同一个文件夹**里，这个文件夹就叫 **`opencode-server-export`**。

推荐做法：把**整个 `opencode-server-export` 文件夹**放在**代码仓库根目录下面**，例如：

```
/opt/enterprise-ai-platform/          ← 代码根目录（你拉取的仓库）
├── docker-compose.yml                ← 19 服务的 compose
├── project_management/
├── api-gateway/
├── ...
└── opencode-server-export/           ← 放这里：本文件夹整体
    ├── docker-compose.opencode.yml
    ├── .env.example
    ├── load-and-run.sh
    ├── join-opencode-tar.sh
    └── 服务器启动说明.txt
```

也就是说：**这两个文件就放在 `opencode-server-export` 里，不要单独拆出去。**

---

## 二、具体步骤（在服务器上）

### 1. 确认目录结构

- 代码根目录：例如 `/opt/enterprise-ai-platform`（按你实际路径）
- 本文件夹路径：`/opt/enterprise-ai-platform/opencode-server-export`（内含 `docker-compose.opencode.yml` 和 `.env.example`）

### 2. 在本文件夹里生成 .env

在 **`opencode-server-export`** 目录下执行：

```bash
cp .env.example .env
```

然后编辑 `.env`，至少改这两项：

- **OPENCODE_WORKSPACE**：服务器上代码仓库的根目录，例如 `OPENCODE_WORKSPACE=/opt/enterprise-ai-platform`
- **EXTERNAL_NETWORK_NAME**：19 服务所在的真实网络名（Compose 会加项目前缀，需和本机一致）。在服务器上执行：
  ```bash
  docker network ls | grep -i enterprise
  ```
  看到类似 `enterprise-ai-platform_enterprise-ai-network` 或 `intl-tst-mcp_enterprise-ai-network` 的**完整名字**，填到 `.env` 里：
  ```bash
  EXTERNAL_NETWORK_NAME=你看到的完整网络名
  ```

### 3. 在本文件夹里启动 OpenCode

仍在 **`opencode-server-export`** 目录下执行：

```bash
cd /opt/enterprise-ai-platform/opencode-server-export
docker compose -f docker-compose.opencode.yml --env-file .env up -d
```

### 4. 检查

```bash
docker compose -f docker-compose.opencode.yml ps
docker logs -f enterprise-ai-opencode
```

看到监听 4096 即可。

**在浏览器打开页面**：
- **http://服务器IP:4096/doc**：API 文档页，任何环境都可打开。
- **http://服务器IP:4096/**：Web 登录与对话界面。若使用**官方镜像**需容器能访问 https://app.opencode.ai；若使用**本地 Web 镜像**（不依赖外网）见 `docs/deployment/OpenCode-本地Web构建与堡垒机上传指南.md`。也可用 /doc 或本机 `opencode attach`。详见 `docs/deployment/OpenCode-Web页面与官方部署说明.md`。

## 三、小结

| 问题 | 答案 |
|------|------|
| docker-compose.opencode.yml 放哪？ | 放在 **opencode-server-export** 文件夹里，不要挪出去 |
| .env.example 放哪？ | 同上，和 docker-compose.opencode.yml 同一文件夹 |
| opencode-server-export 放哪？ | 推荐放在**代码根目录下**，如 `/opt/enterprise-ai-platform/opencode-server-export` |
| 启动命令在哪执行？ | 在 **opencode-server-export** 目录下执行上面的 `docker compose -f docker-compose.opencode.yml ...` |

## 四、报错：network enterprise-ai-network declared as external, but could not be found

**原因**：19 服务虽然已经起了，但 Docker Compose 给网络名加了**项目前缀**，实际名字不是 `enterprise-ai-network`，而是类似 `目录名_enterprise-ai-network` 或 `主机名_enterprise-ai-network`，所以 OpenCode 的 compose 按“未加前缀”的名字去找就报错。

**正确做法（和 19 服务用同一网络）**：

1. 在服务器上查 19 服务所在的**真实网络名**：
   ```bash
   docker network ls | grep -i enterprise
   ```
   记下完整名字，例如：`enterprise-ai-platform_enterprise-ai-network` 或 `intl-tst-mcp_enterprise-ai-network`。

2. 在 **opencode-server-export** 目录下的 `.env` 里增加或修改：
   ```bash
   EXTERNAL_NETWORK_NAME=你上一步看到的完整网络名
   ```
   例如：`EXTERNAL_NETWORK_NAME=enterprise-ai-platform_enterprise-ai-network`。

3. 用原 compose 再起 OpenCode：
   ```bash
   docker compose -f docker-compose.opencode.yml --env-file .env up -d
   ```

这样 OpenCode 会连到 19 服务所在的同一网络。

**若暂时不想和 19 服务同网**，可以用自带网络的 compose（会新建一个独立网络）：
```bash
docker compose -f docker-compose.opencode.standalone.yml --env-file .env up -d
```
