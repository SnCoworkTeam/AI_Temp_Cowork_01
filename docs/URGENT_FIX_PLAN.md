# LuminaOS 功能恢复紧急修复计划

> **目标**: 让系统从"可运行但功能不可用"恢复到"大部分功能可用"
> **时间**: 立即开始，1-2周完成核心修复
> **优先级**: 🔴 阻塞功能恢复 > 🟡 功能改进 > 🟢 优化增强

---

## 🎯 核心问题诊断

基于架构分析，导致功能不可用的**根本原因**：

### 🔴 P0 - 阻塞性问题（导致功能完全不可用）

1. **数据库字段映射不一致** ⚠️ 最紧迫
   - DocumentChunk 无法存储向量 → 知识库搜索不可用
   - KnowledgeGraphNode 字段不匹配 → 知识图谱不可用
   - WorkflowConnection 无外键 → 工作流连接可能出错

2. **API设计问题导致调用失败**
   - GET /auth/sso/login 不符合规范 → SSO登录失败
   - /documents/upload 路径问题 → 文档上传失败
   - 状态码混乱 → 客户端无法正确处理响应

3. **服务启动依赖问题**
   - metadata-service 启动阻塞 → 元数据功能不可用
   - 级联超时 → 服务启动缓慢或失败

4. **错误处理不完整**
   - 异常直接返回500 → 无法诊断问题
   - 缺少错误追踪 → 故障排查困难

## 🔧 实施顺序（推荐）

**为什么这样排序？**
1. **数据库先行**: 数据层问题会影响所有上层功能
2. **错误处理次之**: 能快速诊断其他问题
3. **API修复**: 解除功能阻塞
4. **通信改进**: 提高稳定性
5. **测试验证**: 确保修复有效
