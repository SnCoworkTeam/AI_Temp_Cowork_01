# 内网服务器：本地镜像导出与部署

当服务器在内网、无法直接拉取 Docker 镜像时，可在能联网的本机先构建/拉取镜像，导出为 tar 包，拷贝到服务器后加载并运行。

---

## 一、本机操作（导出）

### 1. 确保本地已构建所需服务

```powershell
cd e:\enterprise-ai-platform
# 已按需构建过，例如：
# .\scripts\build-services-one-by-one.ps1
# 或跳过 web-ui: $env:SKIP_SERVICES="web-ui"; .\scripts\build-services-one-by-one.ps1
```

### 2. 导出镜像

**仅导出 zhgj 19 个服务（推荐）**：

```powershell
cd e:\enterprise-ai-platform
$env:ZHGJ_19="1"; .\scripts\export-docker-images.ps1
```

- 只导出 19 个服务用到的镜像（postgres、redis、qdrant、neo4j + 15 个应用服务），不含 redis-commander、deployment-agent、sap-metadata-agent、project-management、vector-coordinator-service。

**导出 compose 中全部镜像**：

```powershell
.\scripts\export-docker-images.ps1
```

- 默认导出到 **`docker-images-export\`**，包含：
  - 所有 `docker compose config --images` 解析出的镜像的 **.tar** 文件；
  - 复制好的 **docker-compose.yml**、**.env**；
  - 复制好的 **database/init-scripts**。
- 如需指定目录：`.\scripts\export-docker-images.ps1 D:\my-export`
- 强制覆盖已有 tar：`$env:EXPORT_FORCE="1"; .\scripts\export-docker-images.ps1`

### 3. 将整包拷到内网服务器

- **U 盘 / 共享盘**：把 `docker-images-export` 整个文件夹拷到服务器；
- **跳板机 + SCP**：在能同时访问本机和内网的地方执行，例如：
  ```bash
  scp -r docker-images-export user@jump:/tmp/
  # 再从跳板机拷到内网服务器
  ```

## 二、服务器操作（加载并运行）

### Windows 服务器（PowerShell）

1. 进入导出目录（即拷贝过去的 `docker-images-export` 所在路径）：
   ```powershell
   cd E:\docker-images-export
   ```
2. 加载镜像并启动（使用已加载的镜像，不构建）：
   ```powershell
   # 若脚本在项目 scripts 下，可复制 load-and-run.ps1 到导出目录后执行：
   .\load-and-run.ps1
   # 或指定导出目录：
   .\load-and-run.ps1 -ExportDir "E:\docker-images-export"
   ```

### Linux 服务器（Bash，部署目录 /opt/enterprise-ai-platform）

1. 进入部署目录：
   ```bash
   cd /opt/enterprise-ai-platform
   ```
2. 加载镜像并启动：
   ```bash
   for f in *.tar; do [ -f "$f" ] && docker load -i "$f"; done
   docker compose up -d --no-build
   ```
   或使用脚本（若已将 load-and-run.sh 复制到该目录）：
   ```bash
   chmod +x load-and-run.sh
   ./load-and-run.sh
   ```
   （导出在子目录时：`./load-and-run.sh docker-images-export`）

脚本会：

- 对该目录下所有 **.tar** 执行 `docker load -i xxx.tar`；
- 若同目录下有 **docker-compose.yml**，则执行 `docker compose up -d --no-build`（只使用已加载镜像，不拉取、不构建）。

---

## 三、注意事项

1. **项目名一致**：导出时本机 compose 所在目录名（如 `enterprise-ai-platform`）会作为项目名，镜像名为 `enterprise-ai-platform-<服务名>:latest`。服务器上使用同一份 **docker-compose.yml** 和 **.env**，且用 `--no-build`，即可用这些已加载镜像。
2. **数据库与持久化**：首次运行会创建 volume（如 `postgres_data`、`redis_data` 等），数据在服务器本地；若需保留，注意备份或不要删除对应 volume。
3. **端口与 .env**：服务器防火墙需放行所需端口（见《服务清单与服务器配置分析》）；**.env** 中数据库、Redis、各服务地址可按服务器环境修改（如 `DB_HOST=postgres` 保持不变，若改主机名则需同步改 compose/环境变量）。
4. **只部署部分服务**：可先只导出/拷贝需要的镜像 tar 和对应 compose 片段，在服务器上只 `docker load` 这些镜像，并用自定义 compose 或 `docker run` 启动。

---

## 四、脚本一览

| 脚本 | 作用 |
|------|------|
| `scripts/export-docker-images.ps1` | 本机：解析 compose 镜像并导出为 tar，并复制 compose/.env/init-scripts |
| `scripts/load-and-run.ps1` | 服务器（Windows）：加载当前目录下所有 .tar，再 `docker compose up -d --no-build` |
| `scripts/load-and-run.sh` | 服务器（Linux）：同上 |

导出目录内会包含 **docker-compose.yml**、**.env** 和 **load-and-run** 脚本的副本，拷贝整包到内网后，在服务器上进入该目录执行对应 load-and-run 即可完成“本地镜像上传到服务器并直接运行”。
