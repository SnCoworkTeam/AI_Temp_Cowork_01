# 服务器Docker服务手动启动命令

## 准备工作

```bash
# 1. 进入项目目录
cd /opt/enterprise-ai-platform

# 2. 检查.env文件是否存在
ls -la .env

# 3. 如果.env不存在，从示例文件创建
cp env.example .env

# 4. 检查docker-compose.yml文件
cat docker-compose.yml | head -20
```

---

## 第一阶段：启动基础服务（数据库和缓存）

### 1. 启动PostgreSQL数据库
```bash
sudo docker compose up -d postgres
```

等待数据库健康检查通过（约10-30秒）：
```bash
sudo docker compose ps postgres
# 等待状态显示为 "healthy"
```

### 2. 启动Redis缓存
```bash
sudo docker compose up -d redis
```

等待Redis健康检查通过（约5-10秒）：
```bash
sudo docker compose ps redis
# 等待状态显示为 "healthy"
```

---

## 第二阶段：启动核心服务（依赖数据库和缓存）

### 3. 构建并启动MCP Gateway服务
```bash
sudo docker compose up -d --build mcp-gateway
```

等待服务启动（约30-60秒）：
```bash
sudo docker compose logs -f mcp-gateway
# 按Ctrl+C退出日志查看，看到 "Application startup complete" 表示启动成功
```

检查服务状态：
```bash
sudo docker compose ps mcp-gateway
curl http://localhost:8001/api/health
```

## 故障排查

### 如果某个服务启动失败

1. **查看服务日志**：
```bash
sudo docker compose logs <service-name>
```

2. **查看详细错误**：
```bash
sudo docker compose logs --tail=100 <service-name>
```

3. **重启服务**：
```bash
sudo docker compose restart <service-name>
```

4. **重新构建并启动**：
```bash
sudo docker compose up -d --build --force-recreate <service-name>
```

### 如果数据库连接失败

检查数据库是否正常运行：
```bash
sudo docker compose ps postgres
sudo docker compose logs postgres
```

### 如果Redis连接失败

检查Redis是否正常运行：
```bash
sudo docker compose ps redis
sudo docker compose logs redis
```

### 清理并重新开始

如果需要完全重新开始：
```bash
# 停止所有服务
sudo docker compose down

# 清理所有容器和卷（谨慎使用，会删除数据）
sudo docker compose down -v

# 重新启动
# 按照上面的步骤重新执行
```

## 一键启动所有服务（可选）

如果您想一次性启动所有服务（不推荐首次启动，因为可能遇到依赖问题）：

```bash
sudo docker compose up -d --build
```

然后等待所有服务启动完成：
```bash
sudo docker compose ps
```

---

## 注意事项

1. **启动顺序很重要**：必须按照依赖关系顺序启动服务
2. **等待健康检查**：每个服务启动后需要等待健康检查通过
3. **检查日志**：如果服务启动失败，查看日志找出问题
4. **端口冲突**：确保所需端口未被占用
5. **资源要求**：确保服务器有足够的内存和CPU资源
6. **网络连接**：确保服务器可以访问外部网络（下载镜像和依赖）
