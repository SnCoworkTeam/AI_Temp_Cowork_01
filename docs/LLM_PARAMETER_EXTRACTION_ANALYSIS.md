# LLM参数提取不完整问题深度分析

## 问题核心

用户输入：`发送测试邮件给yubin.liu@pcitc.com`

**LLM应该提取但没提取到的参数**：
- `to_emails`: "yubin.liu@pcitc.com" ❌ 缺失
- `subject`: "测试邮件" ❌ 缺失或提取不完整
- `body`: "这是一封测试邮件" ❌ 缺失

## 为什么LLM提取不完整？

### 1. Prompt设计问题分析

#### 当前Prompt的问题

查看 `mcp_tool_agent.py` 的 `analyze_task` 方法中的prompt：

```python
prompt = f"""
作为MCP工具智能体，深度分析以下任务并选择合适的工具。

**任务描述**：
{task_description}

**可用MCP工具列表**（包含完整信息）：
{json.dumps(tools_info, ensure_ascii=False, indent=2)}

**分析要求**：

3. **参数提取**：
   - 从任务描述中提取参数值
   - 从上下文信息中提取参数值
   - 确保所有必需参数都有值
   - 参数值必须符合工具的参数定义（类型、格式等）

**返回JSON格式**：
{{
    "needs_tool": true/false,
    "selected_tool": "工具名称（如果needs_tool为true，必须提供）",
    "optimized_parameters": {{"参数名": "参数值"}},
    ...
}}
"""
```

#### 问题1：缺少Few-Shot示例

**当前问题**：
- Prompt只描述了"要做什么"，但没有提供"怎么做"的示例
- LLM不知道如何从自然语言中提取邮箱地址
- LLM不知道如何处理中文表达（"给XXX发"、"发送给XXX"）

**为什么需要Few-Shot**：
- LLM需要看到具体的例子才能理解任务
- 特别是对于参数提取这种结构化任务
- 示例可以帮助LLM理解：
  - 如何识别邮箱地址
  - 如何从中文表达中提取参数
  - 如何格式化参数值

#### 问题2：参数提取要求不够明确

**当前问题**：
- "从任务描述中提取参数值" - 太模糊
- 没有明确说明：
  - 邮箱地址的识别模式
  - 主题的提取规则
  - 正文的构建逻辑

**应该明确说明**：
- 邮箱地址：查找包含"@"的字符串
- 主题：查找"主题"、"标题"等关键词后的内容，或从任务描述推断
- 正文：查找"正文"、"内容"等关键词后的内容，或使用默认值

#### 问题3：缺少参数验证要求

**当前问题**：
- 只要求"确保所有必需参数都有值"
- 但没有要求LLM在返回前验证参数
- 没有要求LLM在参数缺失时提供默认值

#### 问题4：工具参数定义可能不够清晰

**可能的问题**：
- `tools_info` 中的参数定义可能太复杂
- LLM可能没有正确理解参数格式要求
- 特别是 `to_emails` 可以是字符串或数组，可能让LLM困惑

### 2. LLM能力问题 vs Prompt设计问题

#### 这不是AI能力问题

**证据**：
1. LLM（如DeepSeek）完全有能力识别邮箱地址
2. LLM完全有能力从自然语言中提取结构化信息
3. 问题在于**如何引导LLM做这件事**

#### 这是Prompt设计问题

**根本原因**：
1. **缺少Few-Shot示例**：LLM不知道期望的输出格式
2. **参数提取要求不够具体**：没有明确告诉LLM如何提取
3. **缺少验证步骤**：没有要求LLM在返回前检查参数完整性

### 3. 为什么硬编码不是好方案？

#### 硬编码的问题

1. **不可扩展**：每个工具都需要硬编码逻辑
2. **维护成本高**：需要为每种情况写代码
3. **不够智能**：无法处理复杂或模糊的输入
4. **违背AI设计理念**：应该让AI理解任务，而不是硬编码规则

#### 正确的方向

应该**改进Prompt设计**，让LLM能够：
1. 正确识别和提取参数
2. 处理各种自然语言表达
3. 在参数缺失时提供合理的默认值
4. 验证参数完整性

## 解决方案：改进Prompt设计

### 方案1：添加Few-Shot示例（推荐）

在prompt中添加具体的示例：

```python
prompt = f"""
作为MCP工具智能体，深度分析以下任务并选择合适的工具。

**任务描述**：
{task_description}

**可用MCP工具列表**（包含完整信息）：
{json.dumps(tools_info, ensure_ascii=False, indent=2)}

**参数提取示例**：

示例1：邮件发送
- 输入："发送测试邮件给yubin.liu@pcitc.com"
- 提取：
  - to_emails: "yubin.liu@pcitc.com" (从任务描述中查找包含"@"的字符串)
  - subject: "测试邮件" (从"测试邮件"推断，或使用默认值)
  - body: "这是一封测试邮件。" (使用默认值或从任务描述推断)

示例2：邮件发送（完整）
- 输入："给yubin.liu@pcitc.com发邮件，主题是会议通知，内容是明天下午3点开会"
- 提取：
  - to_emails: "yubin.liu@pcitc.com"
  - subject: "会议通知" (从"主题是"后提取)
  - body: "明天下午3点开会" (从"内容是"后提取)

**参数提取规则**：
1. **邮箱地址提取**：
   - 查找任务描述中包含"@"的字符串
   - 支持模式："给XXX发"、"发送给XXX"、"发给XXX"（XXX是邮箱地址）
   - 如果找到多个邮箱，使用数组格式

2. **主题提取**：
   - 查找"主题："、"标题："、"关于："等关键词后的内容
   - 如果没有明确主题，从任务描述推断（如"测试邮件" -> "测试邮件"）
   - 如果无法推断，使用默认值："邮件"

3. **正文提取**：
   - 查找"正文："、"内容："等关键词后的内容
   - 如果没有明确正文，使用默认值："这是一封邮件。"

4. **参数验证**：
   - 在返回前，检查所有必需参数是否存在
   - 如果参数缺失，使用上述规则补充
   - 确保参数格式符合工具定义（to_emails可以是字符串或数组）

**返回JSON格式**：
{{
    "needs_tool": true/false,
    "selected_tool": "工具名称（如果needs_tool为true，必须提供）",
    "optimized_parameters": {{
        "参数名": "参数值",
        // 确保所有必需参数都存在
    }},
    "execution_strategy": "direct|preprocess|batch",
    "reasoning": "详细的分析过程，包括参数提取逻辑",
    "direct_result": "如果不需要工具且可以直接给出结果，在这里提供"
}}
"""
```

### 方案2：分步骤参数提取

让LLM分步骤提取参数：

```python
# 第一步：识别邮箱地址
email_extraction_prompt = f"""
从以下任务描述中提取邮箱地址：
任务描述：{task_description}

要求：
1. 查找包含"@"的字符串
2. 支持"给XXX发"、"发送给XXX"等模式
3. 返回邮箱地址（字符串或数组）

返回JSON：
{{"emails": ["email1@example.com", "email2@example.com"]}}
"""

# 第二步：提取其他参数
# ...
```

### 方案3：使用Chain-of-Thought

让LLM展示思考过程：

```python
prompt = f"""
分析任务并提取参数，请按以下步骤思考：

步骤1：识别任务类型
- 这是什么类型的任务？（邮件发送、数据查询等）

步骤2：识别工具
- 需要哪个工具？
- 工具的必需参数是什么？

步骤3：提取参数
- 从任务描述中提取每个必需参数
- 对于每个参数，说明提取逻辑

步骤4：验证参数
- 检查所有必需参数是否存在
- 如果缺失，说明如何补充

步骤5：格式化参数
- 确保参数格式符合工具定义
- 返回完整的参数对象

任务描述：{task_description}
工具信息：{json.dumps(tools_info, ensure_ascii=False, indent=2)}
"""
```

## 实施建议

### 优先级1：添加Few-Shot示例

这是最直接有效的方法：
1. 在prompt中添加3-5个邮件发送的示例
2. 覆盖常见场景：
   - 简单邮件（只有邮箱）
   - 完整邮件（有主题和正文）
   - 中文表达（"给XXX发"）
   - 英文表达（"send email to XXX"）

### 优先级2：明确参数提取规则

在prompt中明确说明：
1. 如何识别邮箱地址
2. 如何提取主题
3. 如何提取正文
4. 如何处理缺失参数

### 优先级3：添加参数验证步骤

要求LLM在返回前：
1. 检查所有必需参数
2. 如果缺失，使用规则补充
3. 验证参数格式

## 已实施的改进

### ✅ 改进Prompt设计

1. **添加Few-Shot示例**：
   - 提供了3个邮件发送的具体示例
   - 覆盖简单邮件、完整邮件、中文表达等场景
   - 让LLM看到期望的输出格式

2. **明确参数提取规则**：
   - 详细说明如何提取邮箱地址（查找包含"@"的字符串）
   - 详细说明如何提取主题和正文
   - 明确参数验证要求

3. **强化参数验证要求**：
   - 在prompt中明确要求"必须验证所有必需参数都存在"
   - 要求LLM在返回前检查参数完整性
   - 如果参数缺失，使用规则补充

### ✅ 移除硬编码逻辑

- 移除了`_enhance_tool_parameters`的调用
- 改为只记录警告，让错误暴露出来
- 这样可以通过改进prompt来解决问题，而不是硬编码

### ⚠️ 保留的降级方法

`_enhance_tool_parameters`方法仍然存在，但不再自动调用。可以：
- 作为调试工具，查看参数提取情况
- 作为最后的降级方案（如果LLM完全失败）
- 但主要应该通过改进prompt来解决

## 总结

**问题不是AI能力问题，而是Prompt设计问题**：

1. **缺少Few-Shot示例**：LLM不知道期望的输出格式 ✅ 已修复
2. **参数提取要求不够具体**：没有明确告诉LLM如何提取 ✅ 已修复
3. **缺少验证步骤**：没有要求LLM在返回前检查参数完整性 ✅ 已修复

**解决方案**：
- ✅ 添加Few-Shot示例（最有效）
- ✅ 明确参数提取规则
- ✅ 添加参数验证步骤
- ✅ 移除硬编码逻辑，让LLM自己处理

**不应该**：
- ❌ 依赖硬编码的正则表达式（已移除）
- ❌ 为每个工具写特殊逻辑（已移除）
- ❌ 放弃使用LLM的智能能力（已改进prompt）

- 如果还有问题，继续改进Few-Shot示例
