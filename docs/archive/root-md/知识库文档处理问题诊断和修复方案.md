# 知识库文档处理问题诊断和修复方案

**问题**: 文档上传后处理时间很长，且报错

---

## 问题分析

### 发现的问题

1. **服务状态**: `unhealthy`
2. **处理模式**: 默认使用同步处理（`process_async: False`）
3. **卡住位置**: 文档上传后卡在"Creating document record in database"之后
4. **重复上传**: 日志显示多次重复上传同一文件，说明用户因超时重试

### 可能的原因

1. **文档解析超时**: Word文档解析可能很慢，特别是复杂格式的文档
2. **同步处理阻塞**: 同步处理导致HTTP请求长时间阻塞
3. **向量数据库连接**: ChromaDB连接或初始化可能有问题
4. **嵌入模型加载**: 首次加载嵌入模型可能很慢
5. **内存不足**: 处理大文档时内存不足

---

## 解决方案

### 方案1: 改为异步处理（推荐）

**修改**: `knowledge-base/src/routes/documents_db.py`

```python
# 第119行，改为默认异步处理
process_async: bool = True,  # 改为True，默认异步处理
```

**优点**:
- 立即返回，不阻塞HTTP请求
- 用户可以继续操作
- 后台处理，更稳定

### 方案2: 增加超时和错误处理

**修改**: `knowledge-base/src/services/document_service.py`

1. **增加更详细的日志**
2. **增加超时检测**
3. **增加错误重试机制**

### 方案3: 优化文档处理流程

1. **分批处理**: 大文档分批处理
2. **流式处理**: 使用流式处理减少内存占用
3. **缓存**: 缓存嵌入模型，避免重复加载

## 配置优化

### 超时配置

在 `.env` 文件中调整：

```env
# 文档处理超时（秒）
DOCUMENT_PROCESSING_TIMEOUT=3600  # 1小时
DOCUMENT_PARSING_BASE_TIMEOUT=600  # 10分钟
DOCUMENT_PARSING_TIMEOUT_PER_MB=30  # 每MB增加30秒
```

### 批处理配置

```env
# 嵌入批处理大小
EMBEDDING_BATCH_SIZE=20  # 降低批次大小，减少内存占用
```

## 监控和诊断

### 检查处理中的文档

```sql
SELECT 
    id, 
    filename, 
    status, 
    created_at,
    EXTRACT(EPOCH FROM (NOW() - created_at)) / 60 AS minutes_processing
FROM documents 
WHERE status = 'processing' 
ORDER BY created_at DESC;
```

### 检查错误日志

```bash
docker logs enterprise-ai-knowledge-base --tail 100 | grep -i error
```

### 检查资源使用

