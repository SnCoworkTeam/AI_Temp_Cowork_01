## 二、功能欠缺分析

### 2.1 核心欠缺功能 🔴 P0（最高优先级）

#### 1. **项目群管理（Program/Portfolio Management）** ❌ 完全缺失

**现状**：
- ❌ 没有项目群（Program）概念
- ❌ 无法将多个项目组织成项目群
- ❌ 无法进行项目群级别的计划和资源管理
- ❌ 无法查看项目群整体进度和健康度

**影响**：
- 无法管理大型项目组合
- 无法进行跨项目的资源协调
- 无法进行项目群级别的报告和分析

**优先级**：🔴 P0（最高优先级）

---

#### 2. **项目计划管理（Project Plan/Schedule）** ❌ 完全缺失

**现状**：
- ❌ 没有独立的项目计划模型
- ❌ 任务缺少计划时间线管理
- ❌ 无法创建和管理项目计划模板
- ❌ 无法进行计划版本管理
- ❌ 缺少甘特图视图支持

**影响**：
- 无法进行详细的项目计划制定
- 无法跟踪计划vs实际进度
- 无法进行计划变更管理

**优先级**：🔴 P0（最高优先级）

---

#### 3. **任务依赖关系管理** ⚠️ 部分缺失

**现状**：
- ✅ 任务模型有 `dependencies` 字段（JSONB）
- ❌ 缺少依赖关系的可视化
- ❌ 缺少依赖关系验证（循环依赖检测）
- ❌ 缺少关键路径计算
- ❌ 缺少依赖关系的前端管理界面

**影响**：
- 无法有效管理任务之间的依赖关系
- 无法进行关键路径分析
- 无法自动计算项目完成时间

**优先级**：🟡 P1（高优先级）

---

#### 4. **资源分配和负载管理** ❌ 完全缺失

**现状**：
- ❌ 没有资源（Resource）模型
- ❌ 无法分配资源到任务

- ❌ 无法进行资源冲突检测

**影响**：
- 无法进行资源规划

- 无法避免资源过度分配

**优先级**：🟡 P1（高优先级）

### 3.1 数据模型设计

#### 3.1.1 项目群（Program）模型

```python
class Program(BaseModel):
    """项目群模型"""
    __tablename__ = "pm_programs"
    
    id = Column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    program_code = Column(String(50), unique=True, nullable=False, index=True, comment="项目群编码")
    name = Column(String(200), nullable=False, comment="项目群名称")
    description = Column(Text, nullable=True, comment="项目群描述")
    status = Column(String(20), default="planning", nullable=False, comment="项目群状态")
    manager_id = Column(UUID(as_uuid=True), ForeignKey("users.id"), nullable=True, comment="项目群经理ID")
    start_date = Column(Date, nullable=True, comment="计划开始日期")
    end_date = Column(Date, nullable=True, comment="计划结束日期")
    actual_start_date = Column(Date, nullable=True, comment="实际开始日期")
    actual_end_date = Column(Date, nullable=True, comment="实际结束日期")
    budget = Column(Float, nullable=True, comment="项目群预算")
    actual_cost = Column(Float, nullable=True, comment="实际成本")
    progress_percent = Column(Float, default=0.0, comment="整体进度百分比")
    health_score = Column(Float, default=0.0, comment="健康度评分")
    
    # 关联基础数据
    category_id = Column(UUID(as_uuid=True), ForeignKey("pm_basic_data_categories.id"), nullable=True, comment="项目群分类（从基础数据获取）")
    
    extra_metadata = Column(JSONB, nullable=True, default=dict)
    
    # 关系
    projects = relationship("Project", back_populates="program", cascade="all, delete-orphan")
    plans = relationship("ProgramPlan", back_populates="program", cascade="all, delete-orphan")
```

## 六、关键功能实现要点

### 6.1 从基础数据获取里程碑和任务类型 ✅

**实现方式**：
1. **里程碑类型**：已实现 ✅
   - `Milestone.category_id` 关联 `BasicDataCategory`
   - `category_type == 'milestone'`
   - 创建里程碑时必须选择基础数据中的里程碑类型

2. **任务类型**：需要实现
   - `ProjectPlanTask.category_id` 关联 `BasicDataCategory`
   - `category_type == 'task_type'`
   - 创建计划任务时必须选择基础数据中的任务类型

### 6.2 任务依赖关系管理

**依赖类型**（支持4种）：
- **FS (Finish-to-Start)**：前置任务完成后，后续任务才能开始（默认）
- **SS (Start-to-Start)**：前置任务开始时，后续任务才能开始
- **FF (Finish-to-Finish)**：前置任务完成时，后续任务才能完成
- **SF (Start-to-Finish)**：前置任务开始时，后续任务才能完成

**依赖关系存储**：
```json
{
  "dependencies": [
    {
      "task_id": "uuid",
      "type": "FS",  // FS, SS, FF, SF
      "lag_days": 0  // 滞后天数（可以为负，表示提前）
    }
  ]
}
```

**循环依赖检测**：
- 使用深度优先搜索（DFS）检测循环依赖
- 创建/更新任务时自动检测
- 发现循环依赖时拒绝操作

### 6.3 关键路径计算

**算法**：关键路径法（CPM - Critical Path Method）

**步骤**：
1. **前向计算（Forward Pass）**：
   - 计算每个任务的最早开始时间（ES）和最早结束时间（EF）
   - ES = max(所有前置任务的EF) + lag_days
   - EF = ES + duration_days

2. **后向计算（Backward Pass）**：
   - 计算每个任务的最晚开始时间（LS）和最晚结束时间（LF）
   - LF = min(所有后续任务的LS) - lag_days
   - LS = LF - duration_days

3. **浮动时间计算**：
   - 总浮动时间（Total Float）= LS - ES = LF - EF
   - 自由浮动时间（Free Float）= min(后续任务的ES) - EF

4. **关键路径识别**：
   - 总浮动时间为0的任务为关键任务
   - 所有关键任务组成的路径为关键路径
