# 文档处理内存优化方案

## 问题分析

服务器内存: 16GB
当前问题: 处理大文档(F5业务蓝图报告)时内存耗尽

### 内存占用分析

1. **Embedding模型**: 约1-2GB (sentence-transformers/all-MiniLM-L6-v2)
2. **文档内容**: 根据文档大小，可能几十MB到几百MB
3. **文档chunks**: 假设1个大文档分成500个chunks，每个chunk 1KB = 500KB
4. **Embeddings**: 500个chunks × 384维 × 4字节 = 768KB
5. **向量数据库(Chroma)**: 占用内存存储向量
6. **数据库连接池**: 约100-200MB
7. **Python运行时**: 约300-500MB

**总计**: 约 2-4GB (正常情况下)

### 主要问题

**[document_service.py:407-412](e:\enterprise-ai-platform\knowledge-base\src\services\document_service.py:407-412)**
```python
texts = [chunk.content for chunk in chunks]  # 一次性加载所有chunks到内存
return await loop.run_in_executor(
    None,
    lambda: embedding_manager.encode(texts)  # 一次性生成所有embeddings
)
```

**问题**:
- 如果文档有1000个chunks，每个chunk 2KB，这里就需要 2MB内存
- `embedding_manager.encode()` 会一次性处理所有文本
- 模型推理时会占用更多内存（批处理缓冲区）

## 优化方案

### 方案1: 批处理Embedding生成 ⭐ 推荐

**优点**:
- 显著降低内存占用
- 不需要改变模型
- 实施简单

**实施**:
```python
# 批处理生成embeddings
BATCH_SIZE = 50  # 每批处理50个chunks

all_embeddings = []
for i in range(0, len(chunks), BATCH_SIZE):
    batch_chunks = chunks[i:i+BATCH_SIZE]
    batch_texts = [chunk.content for chunk in batch_chunks]

    # 生成这一批的embeddings
    batch_embeddings = await loop.run_in_executor(
        None,
        lambda: embedding_manager.encode(batch_texts, batch_size=32)
    )
    all_embeddings.extend(batch_embeddings)

    # 更新进度
    progress_tracker.update_step("embedding", completed=i+len(batch_chunks), total=len(chunks))

    # 可选: 清理内存
    import gc
    gc.collect()
```

**内存节省**: 从一次性加载1000个chunks减少到50个，节省约95%的峰值内存

### 方案2: 流式处理

**优点**:
- 进一步降低内存
- 适合超大文档

**缺点**:
- 实施复杂度高
- 需要改动多个模块

### 方案3: 使用更小的模型

当前模型: `sentence-transformers/all-MiniLM-L6-v2` (约90MB)

可选更小模型:
- `paraphrase-MiniLM-L3-v2` (约60MB, 更快)
- `all-MiniLM-L12-v2` (约120MB, 更准确但更慢)

### 方案4: 增加服务器内存

- 当前: 16GB
- 建议: 32GB或更多
- 成本: 根据云服务商定价
