# 数据库连接问题修复说明

## 问题描述
执行动态工作流时出现错误："All connection attempts failed"

## 问题原因
在`metadata_agent.py`的`_ensure_ea_service_initialized`方法中，使用了`lambda: next(get_db())`来获取数据库会话。`get_db()`是一个生成器函数，在`asyncio.run_in_executor`中直接调用会导致连接管理问题。

## 修复方案

### 1. 使用SessionLocal()直接创建会话
- 不再使用`get_db()`生成器
- 直接使用`SessionLocal()`创建数据库会话
- 确保会话工厂已初始化

### 2. 保存数据库会话
- 将数据库会话保存到`self._ea_db`
- 在后续查询中复用该会话
- 避免重复创建连接

### 3. 改进错误处理
- 添加会话关闭的错误处理
- 确保即使出错也能正确清理资源

## 修改内容

### 文件：`agent-service/src/core/agents/metadata_agent.py`

1. **初始化部分**（第84-87行）
   - 添加`self._ea_db = None`用于保存数据库会话

2. **_ensure_ea_service_initialized方法**（第681-715行）
   - 使用`SessionLocal()`而不是`get_db()`
   - 确保会话工厂已初始化
   - 保存会话到`self._ea_db`

3. **_find_data_sources方法**（第740-760行）
   - 优先使用已保存的数据库会话
   - 如果没有，创建新会话并在使用后关闭
   - 添加超时保护（2秒）

## 测试建议

1. **测试EA服务初始化**
   - 验证EA服务能正常初始化
   - 检查日志中是否有连接错误

2. **测试数据源查询**
   - 执行需要数据查询的任务
   - 验证EA知识图谱查询是否正常工作

3. **测试连接稳定性**
   - 多次执行工作流
   - 验证连接不会泄漏

## 注意事项

1. **会话管理**
   - 保存的会话会在agent生命周期内保持打开
   - 如果agent被销毁，会话会自动关闭

2. **连接池**
   - 使用SQLAlchemy的连接池管理
   - 连接会自动回收和复用

3. **错误恢复**
   - 如果连接失败，会降级到原有功能
   - 不会中断主流程
