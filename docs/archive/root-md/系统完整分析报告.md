## 执行摘要

LuminaOS是一个基于微服务架构的企业级AI平台，整合了23个微服务，提供完整的智能体编排、工作流管理、知识库、MCP工具集成和SAP深度集成能力。系统采用现代化技术栈（FastAPI + Next.js + PostgreSQL + Redis + Qdrant），具备强大的实时交互、语义搜索和动态任务编排能力。

**核心指标**:
- **服务数量**: 23个微服务
- **代码规模**: 100,000+ 行代码
- **数据库表**: 50+ 核心表
- **前端页面**: 30+ 独立页面
- **API端点**: 200+ RESTful接口
- **支持模型**: OpenAI、DeepSeek等主流LLM

## 2. 微服务详细分析

### 2.1 Agent Service - 智能体核心服务

**职责**: 智能体管理、对话处理、任务编排、实时交互

#### 核心模块

**Prompt Engine (提示词引擎)**
- 位置: `agent-service/src/core/prompt_engine/`
- 功能:
  - 智能提示词生成（4种任务类型）
  - 动态上下文注入
  - Few-shot Learning支持
  - LRU缓存优化
- 特点:
  - 模板与优化器分离
  - 支持YAML配置
  - 降级策略（fallback）

**Interactive Orchestration Engine (交互式编排引擎)**
- 位置: `agent-service/src/core/interactive_orchestration_engine.py`
- 功能:
  - 实时交互控制（暂停/继续/取消）
  - 用户确认机制
  - 进度追踪
  - 复杂任务分解
- 技术:
  - WebSocket双向通信
  - 异步Future模式
  - 30秒超时控制

**WebSocket Manager (实时通信管理器)**
- 位置: `agent-service/src/core/websocket_manager/`
- 功能:
  - 连接池管理
  - 消息路由和广播
  - 心跳保活
  - 注册式处理器

**API端点**:
```
POST /api/v1/agents/chat                     # 对话接口
POST /api/v1/agents/interactive/chat         # 交互式对话
POST /api/v1/agents/interactive/chat/stream  # 流式对话
GET  /api/v1/ws/{session_id}                # WebSocket连接
```

### 2.2 Knowledge-Base Service - 知识库服务

**职责**: 文档管理、智能检索、向量化、语义搜索

#### 核心模块

**Document Processor (文档处理器)**
- 支持格式: PDF、Word、Excel、Text、Markdown
- 智能分块策略:
  - Fixed: 固定大小（通用文本）
  - Semantic: 语义分块（段落边界）
  - Hierarchical: 层次分块（保留结构）
  - Smart: 自适应（根据内容类型）

**Document Service (文档服务层)**
- 7阶段处理流程:
  1. PARSING (解析)
  2. PREPROCESSING (预处理)
  3. CHUNKING (分块)
  4. EMBEDDING (向量化)
  5. STORING (存储)
  6. QUALITY_CHECK (质量检查)
  7. COMPLETED (完成)
- 质量评估:
  - 完整性评分
  - 可读性评分
  - 独特性评分
- 元数据增强:
  - 自动摘要提取
  - 关键词提取
  - 情感分析

**Embedding Manager (嵌入模型管理器)**
- 默认模型: sentence-transformers/all-MiniLM-L6-v2 (384维)
- 特性:
  - 批量嵌入优化（batch_size=32）
  - L2归一化处理
  - 降级策略（哈希伪随机向量）

**API端点**:
```
POST /api/v1/documents/upload               # 上传文档
GET  /api/v1/documents                      # 文档列表
GET  /api/v1/documents/{id}                 # 文档详情
POST /api/v1/search/semantic                # 语义搜索
POST /api/v1/search/hybrid                  # 混合搜索
GET  /api/v1/knowledge-graph                # 知识图谱
```

### 2.3 DAG-Orchestrator - 工作流编排引擎

**职责**: 复杂任务分解、DAG执行、依赖管理

#### 核心模块

**Task Decomposer (任务分解器)**
- LLM智能分解:
  - 任务类型识别（mcp_tool/workflow/knowledge等）
  - 依赖关系推断
  - 参数提取
- 元数据增强:

**DAG Engine (DAG执行引擎)**

**Backend Clients (后端服务客户端)**
- 集成服务:
  - MCP Gateway

### 2.4 API Gateway - 智能路由网关

**职责**: 统一入口、智能路由、限流熔断、监控

#### 核心功能

**Enhanced Intelligent Router (增强智能路由器)**
- 基于图谱的意图增强
- 缓存优化（MD5哈希，3600秒TTL）
- 超时控制（kb: 2.0s, ms: 1.5s）
- 服务降级（规则匹配fallback）

**路由策略**:
```
TOOL_EXECUTION → MCP Gateway (8001)
WORKFLOW_TASK → Workflow Engine (8002)
KNOWLEDGE_SEARCH → Knowledge Base (8004)
SIMPLE_CHAT → Chat Service (8006)
```

**服务治理**:
- 限流: 60次/分钟（令牌桶算法）
- 熔断: 5次失败阈值，60秒恢复
- 负载均衡: 轮询、随机策略
- 请求重试: 3次，指数退避

**监控指标**:
- `api_gateway_requests_total`
- `api_gateway_request_duration_seconds`
- `api_gateway_requests_in_progress`
- `api_gateway_errors_total`

**API端点**:
```
POST /api/chat/intelligent                  # 智能对话
POST /api/chat/intelligent/stream           # 流式对话
GET  /health                                # 健康检查
GET  /metrics                               # Prometheus指标
```

### 2.5 Unified Intent Service - 统一意图识别

**职责**: 意图理解、语义融合、智能路由

#### 核心创新

**双引擎架构**: LLM + 语义引擎双路召回

**动态融合策略**:
1. **场景1**: LLM高置信度（>0.9）但无语义匹配 → 95%权重LLM
2. **场景2**: 语义引擎高相似度（>0.85） → 100%权重语义
3. **场景3**: 结果冲突（业务领域不一致） → 降低置信度
4. **场景4**: 加权平均（动态权重）

**Few-shot Learning增强**:
- 3个标准示例
- 明确意图分类规则
- 实体提取方法

**技术亮点**:
- LLM+语义引擎双路召回
- 自动参数填充
- 缓存优化（3600秒TTL）
- 降级策略（规则匹配）

## 3. 数据库设计深度解析

**技术栈**:
- PostgreSQL 15（支持JSONB、UUID、ENUM）
- ORM: SQLAlchemy 2.0
- 迁移: Alembic
- 验证: Pydantic

**设计原则**:
- 多租户支持（基于角色权限）
- 审计追踪（时间戳、操作日志）
- 数据版本化（工作流、提示词）
- JSONB灵活存储
- 严格外键约束

### 3.3 索引策略

**B-Tree索引** (默认)
```sql
-- 单列索引
CREATE INDEX idx_users_username ON users (username);
CREATE INDEX idx_users_email ON users (email) UNIQUE;

-- 复合索引
CREATE INDEX idx_workflow_execution_status ON workflow_executions (workflow_id, status);
CREATE INDEX idx_documents_kb_id ON documents (knowledge_base_id);
```

**GIN索引** (数组、JSONB)
```sql
-- 数组字段
CREATE INDEX idx_documents_tags ON documents USING GIN (tags);

-- JSONB字段
CREATE INDEX idx_metadata_gin ON documents USING GIN (document_metadata);
```

**部分索引**
```sql
-- 只索引活跃用户
CREATE INDEX idx_users_active ON users (username) WHERE status = 'active';

-- 只索引未完成的执行
CREATE INDEX idx_executions_pending ON workflow_executions (workflow_id)
WHERE status IN ('pending', 'running');
```

**表达式索引**
```sql
-- JSONB字段提取
CREATE INDEX idx_metadata_category ON documents ((document_metadata->>'category'));

-- 小写转换
CREATE INDEX idx_users_email_lower ON users (LOWER(email));
```

### 3.4 数据流转策略

#### 知识库文档处理流程
```
1. Document Upload → documents (status: uploading)
2. Document Processing → document_chunks (content, chunk_index)
3. Vector Embedding → document_chunks.embedding (JSONB)
4. Knowledge Graph → knowledge_graph_nodes/edges
5. Completion → documents.status = processed
```

#### 工作流执行流程
```
1. Workflow Creation → workflow_definitions/nodes/connections
2. Execution Initiation → workflow_executions (status: pending)
3. Node Execution → node_results update, progress calculation
4. Tool/Agent Invocation → mcp_tool_executions/agent_execution_records
5. Completion → workflow_executions.status = completed
```

## 4. 核心业务功能实现

### 4.1 智能对话系统

**完整流程**:
```
用户输入 → API Gateway
         → Enhanced Router (意图分析 + 语义增强)
         → Agent Service (Prompt Engine生成优化提示词)
         → [简单对话] → Chat Service → LLM → 返回结果
         → [复杂任务] → DAG Orchestrator → 任务分解 → 并行执行 → 聚合结果
         → WebSocket实时反馈
```

**技术特点**:
- 双引擎融合（LLM + 语义引擎）
- 流式响应（SSE）
- 实时进度追踪
- 用户交互控制

### 4.2 动态工作流生成

**流程设计**:
```
用户需求 → LLM分析 → 工作流设计 → 验证 → 分层执行 → 实时反馈
```

**核心能力**:
- 自动任务分解
- 依赖关系推断
- 并行执行优化
- 容错机制

**示例**: 创建采购订单
```
节点1: 验证供应商 (并行)
节点2: 验证物料 (并行)
节点3: 创建订单 (依赖节点1,2)
```

### 4.3 知识库增强对话

**功能**:
- 文档上传与处理（7阶段流程）
- 智能分块（4种策略）
- 向量化（384维嵌入）
- 语义搜索（混合检索）
- 知识图谱（实体关系）
- 答案溯源（来源追踪）

**技术实现**:
- ChromaDB向量存储
- Sentence Transformers嵌入
- 批量优化（batch_size=32）
- 双写策略（PostgreSQL + ChromaDB）

### 4.4 企业语义能力图谱

**三层架构**:
```
业务层: business_activities (业务意图)
   ↓
能力层: capability_units (能力抽象)
   ↓
```

```
6. 刷新失败 → 重新登录
```
