# 树形表格组件实现方案分析

**日期**: 2025-12-27
**功能**: 项目计划管理的树形表格组件

---

## 一、现有代码结构分析

### 1.1 当前实现方式

**文件**: `web-ui/src/app/projects/[id]/page.tsx`

- **布局**: 左右分栏布局
  - 左侧（1/3宽度）：树形结构（`PlanTreeView`组件）
  - 右侧（2/3宽度）：任务列表（表格形式）

- **数据来源**:
  - 通过 `GET /api/v1/projects/{project_id}/plans/{plan_id}/tree` 获取树形结构
  - 通过 `GET /api/v1/tasks?project_id={project_id}&phase_id={phase_id}` 获取任务列表
  - **数据来源于项目模板**：计划创建时基于模板的 `template_structure` 字段自动生成阶段

- **组件结构**:
  ```typescript
  ProjectPlansByPhaseSection
    ├── 左侧: TreeNodeWithSelect (树形选择)
    └── 右侧: 任务表格 (显示选中阶段的任务)
  ```

### 1.2 数据模型

**后端模型** (`database/src/models/project_models.py`):
- `ProjectTemplate.template_structure` (JSONB): 存储模板结构
  ```json
  {
    "phases": [
      {
        "category_id": "uuid",
        "name": "需求分析",
        "sequence": 0
      }
    ]
  }
  ```
- `ProjectPlan`: 项目计划
- `ProjectPhase`: 项目阶段（从模板创建，只读）
- `ProjectPlanTask`: 计划任务（可编辑）

**前端类型** (`web-ui/src/types/project.ts`):
```typescript
interface PlanTreeNode {
  id: string;

  name: string;
  is_readonly: boolean;  // 阶段为true，任务为false

  // ... 其他字段

```

## 二、新需求分析

### 2.1 核心需求

1. **统一表格展示**
   - 将阶段和任务整合在同一个表格中
   - 不再使用左右分栏布局

2. **树形结构**
   - 支持展开/折叠
   - 层级缩进显示
   - 阶段和任务使用不同视觉区分

3. **拖拽功能**
   - 支持任务拖拽排序
   - 支持跨层级拖拽（任务可拖到其他阶段）
   - 阶段节点不可拖拽（只读）

4. **行内编辑**
   - 双击或点击字段进入编辑模式
   - 支持编辑：负责人、时间范围、进度、状态、优先级、预估工时

5. **状态联动**
   - 阶段进度自动计算（基于子任务进度加权平均）
   - 所有子任务完成时，阶段自动标记为"已完成"

### 2.2 表格列设计

| 列名 | 宽度 | 说明 |
|------|------|------|
| 名称 | 300px | 层级缩进 + 图标 + 名称 + 操作按钮 |
| 负责人 | 120px | 仅任务显示，可编辑 |
| 时间范围 | 240px | 仅任务显示，可编辑 |
| 进度 | 150px | 阶段自动计算，任务可编辑 |
| 状态 | 120px | 阶段/任务不同状态，可编辑 |
| 优先级 | 100px | 仅任务显示，可编辑 |
| 预估工时 | 120px | 仅任务显示，可编辑 |

#### 3.2.2 阶段进度自动计算

```typescript
const calculatePhaseProgress = (phaseId: string): number => {
  const phase = tree.find((node) => node.id === phaseId);
  if (!phase || !phase.children) return 0;

  const tasks = phase.children.filter((child) => child.type === 'task');
  const totalProgress = tasks.reduce((sum, task) => sum + (task.progress_percent || 0), 0);
  return Math.round(totalProgress / tasks.length);
};
```

## 四、与现有代码的差异

### 4.1 布局差异

| 项目 | 现有实现 | 新实现 |
|------|---------|--------|
| 布局方式 | 左右分栏 | 单一表格 |
| 左侧 | 树形结构（1/3宽度） | 整合到表格第一列 |
| 右侧 | 任务列表（2/3宽度） | 整合到表格其他列 |
| 交互方式 | 点击左侧节点，右侧显示任务 | 直接在表格中展开/折叠 |

### 4.2 数据获取差异

| 项目 | 现有实现 | 新实现 |
|------|---------|--------|
| 树形结构 | `GET /plans/{plan_id}/tree` | 相同 |
| 任务列表 | `GET /tasks?phase_id={phase_id}` | 不需要单独获取，从树形结构中提取 |
| 数据更新 | 选择节点后获取任务 | 直接在表格中编辑 |

### 4.3 功能差异

| 功能 | 现有实现 | 新实现 |
|------|---------|--------|
| 展开/折叠 | 树形组件内置 | 表格行内展开/折叠 |
| 拖拽 | 不支持 | 支持（需要 @dnd-kit） |
| 行内编辑 | 不支持 | 支持 |
| 状态联动 | 不支持 | 支持（阶段进度自动计算） |

## 五、数据来源保证

### 5.1 项目计划来源于模板

**后端逻辑** (`project_management/src/routes/project_plans.py`):

```python
# 创建计划时，如果提供了模板ID
if template_id:
    template = db.query(ProjectTemplate).filter(...).first()
    if template and template.template_structure:
        phases_data = template.template_structure.get("phases", [])
        # 从模板结构创建阶段
        for phase_data in phases_data:
            category = db.query(BasicDataCategory).filter(...).first()
            if category:
                phase = ProjectPhase(
                    project_id=project_uuid,
                    category_id=category_id,
                    name=category.name,  # 从基础数据获取
                    sequence=phase_data.get("sequence", 0),
                )
                db.add(phase)
```

**前端保证**:
- 树形表格组件接收的 `tree` 数据来自 `GET /plans/{plan_id}/tree`
- 该接口返回的数据结构已经包含了从模板创建的阶段
- 阶段节点的 `is_readonly: true` 标识确保阶段不可编辑

### 5.2 阶段数据来源于基础数据

- 阶段名称、编码、顺序都从 `BasicDataCategory` (category_type='project_phase') 获取
- 模板的 `template_structure` 只存储 `category_id`，不存储阶段名称
- 创建计划时，从基础数据同步阶段信息

## 七、注意事项

### 7.1 数据一致性

- 阶段节点始终是只读的（`is_readonly: true`）
- 任务节点可以编辑和删除
- 阶段数据来源于模板，不能手动修改

### 7.2 性能优化

- 使用 `useMemo` 缓存扁平化数据
- 使用 `useCallback` 缓存回调函数
- 大量数据时考虑虚拟滚动

### 7.3 用户体验

- 拖拽时显示视觉引导线
- 编辑时提供清晰的视觉反馈
- 保存失败时显示错误提示

## 八、总结

新的树形表格组件将提供更直观、更高效的项目计划管理体验：

1. **统一视图**: 阶段和任务在同一表格中，一目了然
2. **交互优化**: 支持拖拽、行内编辑，操作更便捷
3. **智能联动**: 阶段进度自动计算，减少手动维护
4. **数据保证**: 确保计划数据来源于模板，阶段数据来源于基础数据
