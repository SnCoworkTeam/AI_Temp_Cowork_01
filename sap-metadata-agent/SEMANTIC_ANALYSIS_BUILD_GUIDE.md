# SAP元数据语义分析构建指南

## 📋 概述

本文档说明如何为已构建的SAP元数据生成语义分析索引。语义分析索引将SAP元数据转换为可搜索的语义文档，存储到知识库服务中，支持智能语义搜索。

## 🎯 功能特性

- ✅ **分批处理**: 支持大批量元数据的分批处理，避免内存和超时问题
- ✅ **断点续传**: 支持中断后从上次位置继续构建
- ✅ **进度跟踪**: 自动保存构建进度，可随时查看
- ✅ **错误重试**: 自动重试失败的批次，提高成功率
- ✅ **详细日志**: 提供详细的构建日志和统计信息

## 📦 前置条件

1. **SAP元数据已构建**: 确保元数据服务中已有SAP元数据
2. **知识库服务运行**: 确保知识库服务正常运行
3. **环境变量配置**: 配置必要的服务URL

### 环境变量

```bash
# 元数据服务URL
export METADATA_SERVICE_URL=http://localhost:8005

# 知识库服务URL
export KNOWLEDGE_BASE_URL=http://localhost:8004

# 批次大小（可选，默认50）
export SEMANTIC_BATCH_SIZE=50
```

## 🚀 使用方法

### 基本用法

```bash
# 从头开始构建
cd sap-metadata-agent
python build_semantic_analysis.py
```

### 高级用法

```bash
# 指定批次大小（处理速度更快，但占用更多内存）
python build_semantic_analysis.py --batch-size 100

# 从指定偏移量开始（用于跳过已处理的数据）
python build_semantic_analysis.py --assets-offset 1000 --entities-offset 0

# 从进度文件恢复（中断后继续）
python build_semantic_analysis.py --resume

# 强制从头开始（忽略进度文件）
python build_semantic_analysis.py --no-resume
```

## 📊 构建流程

### 步骤1: 处理数据资产

脚本会从元数据服务获取所有SAP数据资产，分批处理：

1. 获取一批数据资产（默认50个）
2. 转换为SAP格式
3. 创建语义文档
4. 存储到知识库
5. 更新进度

### 步骤2: 处理业务实体

处理完数据资产后，继续处理业务实体：

1. 获取一批业务实体
2. 转换为SAP格式
3. 创建语义文档
4. 存储到知识库
5. 更新进度

## ⚙️ 配置参数

### 批次大小

批次大小影响处理速度和资源占用：

- **小批次（10-30）**: 内存占用低，但处理速度慢
- **中批次（50-100）**: 平衡速度和资源（推荐）
- **大批次（200+）**: 速度快，但可能超时或内存不足

### 重试配置

在脚本中可调整：

```python
MAX_RETRIES = 3  # 最大重试次数
RETRY_DELAY = 2  # 重试延迟（秒）
BATCH_DELAY = 1  # 批次间延迟（秒）
```

## 🐛 故障排除

### 问题1: 知识库服务连接失败

**症状**: 错误信息显示无法连接到知识库服务

**解决方案**:
```bash
# 检查知识库服务是否运行
curl http://localhost:8004/api/health

# 检查环境变量
echo $KNOWLEDGE_BASE_URL

# 如果使用Docker，确保使用正确的URL
export KNOWLEDGE_BASE_URL=http://knowledge-base:8004
```

### 问题2: 请求超时

**症状**: 某些批次处理超时

**解决方案**:
- 减小批次大小: `--batch-size 20`
- 增加超时时间（修改脚本中的 `timeout=120.0`）

### 问题3: 内存不足

**症状**: 处理过程中内存占用过高

**解决方案**:
- 减小批次大小: `--batch-size 10`
- 增加批次间延迟（修改脚本中的 `BATCH_DELAY`）

### 问题4: 部分文档索引失败

**症状**: 统计显示有失败的文档

**解决方案**:
- 检查知识库服务日志
- 检查文档内容是否过大
- 使用 `--resume` 继续构建，失败的文档会在重试时处理

## 🔄 断点续传

如果构建过程中断，可以使用 `--resume` 参数继续：

```bash
# 从上次中断的位置继续
python build_semantic_analysis.py --resume
```

脚本会自动：
1. 加载进度文件
2. 从上次的偏移量继续
3. 更新统计信息

4. **资源监控**: 监控CPU、内存、网络使用情况
