## 排查步骤

### 1. 检查前端是否运行

```powershell
# 检查3000端口是否在监听
netstat -ano | findstr ":3000"
```

如果前端未运行，启动前端：
```powershell
cd web-ui
npm run dev
```

### 2. 检查浏览器控制台

打开浏览器开发者工具（F12），查看：
- **Console标签**: 查看是否有JavaScript错误
- **Network标签**: 查看登录请求的状态和响应

### 3. 检查网络请求

在Network标签中，找到 `/auth/login` 请求，检查：
- **请求URL**: 应该是 `http://127.0.0.1:8003/auth/login`
- **请求方法**: POST
- **请求头**: 应该包含 `Content-Type: application/json`
- **请求体**: 应该包含 `{"username":"admin","password":"admin123456"}`
- **响应状态**: 应该是 200
- **CORS头**: 应该包含 `Access-Control-Allow-Origin`

### 4. 常见问题

#### 问题1: CORS错误
**症状**: 浏览器控制台显示 `CORS policy` 错误

**解决**: 
- 检查auth服务的CORS配置（已配置允许 `http://localhost:3000`）
- 确认前端访问的URL是 `http://localhost:3000` 而不是其他地址

#### 问题2: 网络连接错误
**症状**: `Failed to fetch` 或 `Network error`

**解决**:
- 确认auth服务正在运行: `netstat -ano | findstr ":8003"`
- 测试后端API: 
  ```powershell
  $body = @{username="admin"; password="admin123456"} | ConvertTo-Json
  Invoke-WebRequest -Uri http://127.0.0.1:8003/auth/login -Method POST -Body $body -ContentType "application/json"
  ```

#### 问题3: 401未授权错误
**症状**: 登录返回401状态码

**解决**:
- 确认用户名和密码正确
- 检查数据库中用户是否存在
- 查看auth服务日志

#### 问题4: 前端环境变量未设置
**症状**: 前端使用错误的API地址

**解决**:
- 检查 `web-ui/.env.local` 或 `web-ui/.env` 文件
- 确认 `NEXT_PUBLIC_AUTH_SERVICE_URL=http://127.0.0.1:8003`
- 重启前端服务

### 5. 手动测试API

使用PowerShell测试登录：

```powershell
$body = @{
    username = "admin"
    password = "admin123456"
} | ConvertTo-Json

Invoke-WebRequest -Uri http://127.0.0.1:8003/auth/login `
    -Method POST `
    -Body $body `
    -ContentType "application/json" `
    -UseBasicParsing
```

如果这个命令成功，说明后端API正常，问题在前端。

### 6. 检查前端代码

确认前端使用的API地址：
- 打开 `web-ui/src/lib/api/auth.ts`
- 确认 `AUTH_SERVICE_URL` 是 `http://127.0.0.1:8003`

### 7. 清除浏览器缓存

有时浏览器缓存可能导致问题：
- 按 `Ctrl+Shift+Delete` 清除缓存
- 或使用无痕模式测试
