## 执行策略

### 阶段一：评估当前状态（1-2小时）

**目标**：了解每个服务的当前测试覆盖率和失败情况

**步骤**：

1. 运行所有服务的测试，获取当前覆盖率

3. 识别缺失的测试覆盖区域

**输出**：

- 每个服务的当前覆盖率报告
- 缺失测试覆盖的区域列表
- 优先级排序（从低覆盖率到高覆盖率）

### 阶段二：逐个服务提升覆盖率（每个服务2-4小时）

**执行顺序**（按依赖关系和复杂度）：

**每个服务的执行流程**：

#### 步骤1：分析覆盖率报告

- 识别覆盖率低于80%的模块
- 列出需要测试的函数/类
- 确定测试优先级（关键路径优先）

#### 步骤2：添加缺失的测试

- 为未覆盖的模块创建测试
- 重点覆盖：
  - 服务层方法（CRUD操作）
  - API路由端点
  - 业务逻辑函数
  - 错误处理路径
  - 边界条件

#### 步骤3：修复测试失败

- 修复导入错误
- 修复Mock对象设置
- 修复断言逻辑
- 修复数据库连接问题

#### 步骤4：上传并验证

- 上传修复后的代码到服务器
- 运行测试验证覆盖率
- 确保所有测试通过

#### 步骤5：重复循环

- 如果覆盖率未达到80%，返回步骤2
- 继续添加测试直到达到目标

## 测试-修复-上传循环流程

### 自动化脚本

使用 `scripts/deployment/test-and-fix.ps1` 进行自动化循环：

```powershell
.\scripts\deployment\test-and-fix.ps1
```

**脚本功能**：

1. 连接到服务器
2. 运行所有测试
3. 解析测试结果和覆盖率
4. 识别失败和低覆盖率
5. 等待修复后上传
6. 重复循环

### 手动循环步骤

如果自动化脚本不可用，手动执行：

1. **运行测试**：
   ```bash
   ssh -F remote.ssh enterprise-ai-server "cd /opt/enterprise-ai-platform && python3 -m pytest <service>/tests -v --cov=<service>/src --cov-report=term-missing"
   ```

2. **分析结果**：

   - 查看失败的测试
   - 查看覆盖率报告
   - 识别需要添加的测试

3. **修复和添加测试**：

   - 修复失败的测试
   - 添加缺失的测试用例
   - 确保测试覆盖关键路径

4. **上传代码**：
   ```powershell
   .\scripts\deployment\sync-to-server.ps1
   ```


或使用scp直接上传：

   ```bash
   scp -i enterprise_ai_platform.pem <file> ubuntu@43.143.139.197:/opt/enterprise-ai-platform/<path>
   ```

5. **验证**：

   - 重新运行测试
   - 检查覆盖率是否提升
   - 确保所有测试通过

6. **重复**：

   - 如果覆盖率未达到80%，返回步骤2
   - 继续循环直到达到目标
