# 统一代码质量检查配置使用指南

## 📋 快速开始

### 前端服务 (web-ui)

#### 1. 安装依赖

```bash
cd web-ui
npm install
```

#### 2. 配置已自动应用

以下文件已自动配置：
- `.eslintrc.json` - 继承统一ESLint配置
- `.prettierrc.js` - 使用统一Prettier配置
- `tsconfig.json` - 继承统一TypeScript配置
- `.lintstagedrc.js` - Git提交前检查配置

#### 3. 初始化Husky (可选)

```bash
cd web-ui
npx husky init
```

然后复制 `.husky/pre-commit` 文件内容：

```bash
#!/usr/bin/env sh
. "$(dirname "$0")/_/husky.sh"

npx lint-staged
```

#### 4. 测试配置

```bash
# 检查ESLint
npm run lint

# 格式化代码
npx prettier --write "src/**/*.{ts,tsx,js,jsx}"

# 检查TypeScript
npx tsc --noEmit
```

### 后端服务 (project_management)

#### 1. 配置文件已自动复制

以下文件已自动复制到 `project_management/`：
- `pyproject.toml` - Black/isort/Ruff配置
- `mypy.ini` - mypy类型检查配置
- `.pylintrc` - Pylint代码质量配置

#### 2. 安装工具 (如果未安装)

```bash
pip install black isort ruff mypy pylint
```

#### 3. 运行检查

```bash
cd project_management

# 格式化代码
black src/

# 排序导入
isort src/

# 静态分析
ruff check src/

# 类型检查
mypy src/ --config-file mypy.ini

# 代码质量检查
pylint src/
```

## 🚀 CI/CD集成

### GitHub Actions示例

```yaml
name: Code Quality Check

on: [push, pull_request]

jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      # 前端检查
      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '20'

      - name: Install dependencies
        run: |
          cd web-ui
          npm ci

      - name: Run ESLint
        run: |
          cd web-ui
          npm run lint

      # 后端检查
      - name: Setup Python
        uses: actions/setup-python@v4
        with:
          python-version: '3.10'

      - name: Install Python dependencies
        run: |
          pip install black isort ruff mypy

      - name: Run Black
        run: black --check project_management/src/

      - name: Run isort
        run: isort --check-only project_management/src/

      - name: Run Ruff
        run: ruff check project_management/src/
```

## 📚 最佳实践

### 1. 提交前检查

确保在提交前运行检查：

```bash
# 前端
cd web-ui
npm run lint
npx prettier --check "src/**/*.{ts,tsx}"

# 后端
cd project_management
black --check src/
isort --check-only src/
ruff check src/
```

### 2. 自动修复

大多数问题可以自动修复：

```bash
# 前端
npx prettier --write "src/**/*.{ts,tsx}"
npm run lint -- --fix

# 后端
black src/
isort src/
ruff check --fix src/
```

### 3. 逐步启用严格规则

建议分阶段启用严格规则：
1. 第一阶段：格式化（Black/Prettier）
2. 第二阶段：静态分析（ESLint/Ruff）
3. 第三阶段：类型检查（TypeScript/mypy）

## ❓ 常见问题

### Q: 如何禁用某个规则？

**A**: 在项目的配置文件中覆盖规则：

```json
// .eslintrc.json
{
  "extends": ["../config-standards/packages/eslint-config"],
  "rules": {
    "@typescript-eslint/no-explicit-any": "off"
  }
}
```

### Q: 如何添加项目特定规则？

**A**: 在继承基础配置后添加：

```json
// .eslintrc.json
{
  "extends": ["../config-standards/packages/eslint-config"],
  "rules": {
    "custom-rule": "error"
  }
}
```

### Q: Husky钩子不工作？

**A**: 检查：
1. 是否正确初始化：`npx husky init`
2. `.husky/pre-commit` 文件是否有执行权限
3. 是否安装了lint-staged

### Q: Python类型检查错误太多？

**A**: 可以逐步启用：
1. 先修复关键文件
2. 使用 `# type: ignore` 临时忽略
3. 逐步添加类型注解
