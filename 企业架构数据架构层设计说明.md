## 📊 一、数据架构层概述

### 1.1 TOGAF数据架构域

```yaml
TOGAF数据架构域:
  定义: 数据架构描述支持业务和应用架构的数据资产
  
  包含内容:
    1. 数据实体 (Data Entity)
       - 业务数据实体
       - 数据表
       - 数据字段
    
    2. 数据模型 (Data Model)
       - 逻辑数据模型
       - 物理数据模型
       - 数据模型关系
    
    3. 数据流 (Data Flow)
       - 系统间数据流
       - 数据集成
       - 数据同步
    
    4. API接口 (API Interface)
       - REST API
       - SOAP API
       - 其他接口
```

### 1.2 数据架构层在架构中的位置

```
业务层 (Business Layer)
  ↓ USES / PRODUCES / CONSUMES
数据架构层 (Data Architecture Layer) ⭐ 新增
  ├─ 数据实体 (Data Entity): 业务数据实体、数据表
  ├─ 数据模型 (Data Model): 逻辑模型、物理模型
  ├─ 数据流 (Data Flow): 系统间数据流
  └─ API接口 (API Interface): REST API、SOAP API等
  ↓ STORED_IN / EXPOSED_BY / CONNECTS_TO
应用层 (Application Layer)
  ↓ RUNS_ON / DEPENDS_ON
技术架构层 (Technology Architecture Layer)
```

## 🗄️ 二、数据模型设计

### 2.1 数据实体模型

```python
class DataEntity(BaseModel, TimestampMixin):
    """数据实体模型"""
    __tablename__ = "data_entities"
    
    id = Column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    name = Column(String(255), nullable=False, index=True, comment="实体名称")
    code = Column(String(100), nullable=True, unique=True, index=True, comment="实体编码")
    description = Column(Text, nullable=True, comment="实体描述")
    entity_type = Column(String(100), nullable=True, index=True, comment="实体类型: Table, View, Entity等")
    schema_name = Column(String(255), nullable=True, comment="Schema名称")
    table_name = Column(String(255), nullable=True, comment="表名（如果是数据库表）")
    application_system_id = Column(UUID(as_uuid=True), ForeignKey("application_systems.id"), nullable=True, index=True, comment="所属应用系统ID")
    technology_system_id = Column(UUID(as_uuid=True), ForeignKey("technology_systems.id"), nullable=True, index=True, comment="存储的技术系统ID（数据库）")
    data_model_id = Column(UUID(as_uuid=True), ForeignKey("data_models.id"), nullable=True, index=True, comment="所属数据模型ID")
    neo4j_node_id = Column(String(255), nullable=True)
    meta_data = Column(JSONB, nullable=True, default=dict, comment="扩展元数据")
    
    # meta_data示例
    # {
    #   "entity_type": "Table",  # Table, View, Entity
    #   "schema": "SAP",
    #   "table_name": "MARA",  # SAP物料主数据表
    #   "row_count": 1000000,
    #   "columns": ["MATNR", "MAKTX", "MEINS"],
    #   "primary_key": ["MATNR"],
    #   "indexes": ["IDX_MARA_MATNR"]
    # }
    
    # 关系
    application_system = relationship("ApplicationSystem", backref="data_entities")
    technology_system = relationship("TechnologySystem", backref="stored_entities")
    data_model = relationship("DataModel", backref="entities")
```

### 2.3 API接口模型

```python
class APIInterface(BaseModel, TimestampMixin):
    """API接口模型"""
    __tablename__ = "api_interfaces"
    
    id = Column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    name = Column(String(255), nullable=False, index=True, comment="接口名称")
    code = Column(String(100), nullable=True, unique=True, index=True, comment="接口编码")
    description = Column(Text, nullable=True, comment="接口描述")
    interface_type = Column(String(100), nullable=True, index=True, comment="接口类型: REST, SOAP, GraphQL等")
    endpoint = Column(String(500), nullable=True, comment="接口端点")
    method = Column(String(50), nullable=True, comment="HTTP方法: GET, POST, PUT, DELETE等")
    application_system_id = Column(UUID(as_uuid=True), ForeignKey("application_systems.id"), nullable=True, index=True, comment="所属应用系统ID")

    neo4j_node_id = Column(String(255), nullable=True)
    meta_data = Column(JSONB, nullable=True, default=dict)
    
    # meta_data示例
    # {
    #   "interface_type": "REST",
    #   "endpoint": "/api/v1/materials",
    #   "method": "GET",
    #   "version": "v1",
    #   "authentication": "OAuth2",
    #   "request_schema": {...},
    #   "response_schema": {...}
    # }
    
    # 关系
    application_system = relationship("ApplicationSystem", backref="api_interfaces")
```

### 2.4 数据流模型

```python
class DataFlow(BaseModel, TimestampMixin):
    """数据流模型"""
    __tablename__ = "data_flows"
    
    id = Column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    name = Column(String(255), nullable=False, index=True, comment="数据流名称")
    description = Column(Text, nullable=True, comment="数据流描述")
    flow_type = Column(String(100), nullable=True, index=True, comment="数据流类型: ETL, Real-time, Batch等")
    source_entity_id = Column(UUID(as_uuid=True), ForeignKey("data_entities.id"), nullable=True, index=True, comment="源数据实体ID")
    target_entity_id = Column(UUID(as_uuid=True), ForeignKey("data_entities.id"), nullable=True, index=True, comment="目标数据实体ID")
    source_system_id = Column(UUID(as_uuid=True), ForeignKey("application_systems.id"), nullable=True, index=True, comment="源系统ID")
    target_system_id = Column(UUID(as_uuid=True), ForeignKey("application_systems.id"), nullable=True, index=True, comment="目标系统ID")
    frequency = Column(String(100), nullable=True, comment="数据流频率: Real-time, Daily, Weekly等")
    neo4j_node_id = Column(String(255), nullable=True)
    meta_data = Column(JSONB, nullable=True, default=dict)
    
    # 关系
    source_entity = relationship("DataEntity", foreign_keys=[source_entity_id], backref="source_flows")
    target_entity = relationship("DataEntity", foreign_keys=[target_entity_id], backref="target_flows")
    source_system = relationship("ApplicationSystem", foreign_keys=[source_system_id], backref="source_data_flows")
    target_system = relationship("ApplicationSystem", foreign_keys=[target_system_id], backref="target_data_flows")
```

## 🔗 三、关系设计

### 3.1 数据实体关系

```cypher
// 数据实体存储在技术系统（数据库）上
(:DataEntity {name: "物料主数据表", table_name: "MARA"})-[:STORED_IN {
  schema: "SAP",
  database: "SAP_ERP_DB"
}]->(:TechnologySystem {name: "Oracle-SAP-ERP", system_type: "DatabaseSystem"})

// 数据实体属于应用系统
(:DataEntity {name: "物料主数据表"})-[:BELONGS_TO]->(:ApplicationSystem {name: "SAP ERP"})

// 数据实体属于数据模型
(:DataEntity)-[:PART_OF]->(:DataModel {name: "SAP物料数据模型"})
```

### 3.2 API接口关系

```cypher
// API接口由应用系统提供
(:ApplicationSystem {name: "SAP ERP"})-[:PROVIDES]->(:APIInterface {
  name: "物料查询接口",
  endpoint: "/api/v1/materials",
  method: "GET"
})

// API接口调用数据实体
(:APIInterface {name: "物料查询接口"})-[:QUERIES]->(:DataEntity {name: "物料主数据表"})

// 应用系统调用其他系统的API接口
(:ApplicationSystem {name: "WMS系统"})-[:CALLS]->(:APIInterface {
  name: "物料查询接口",
  endpoint: "/api/v1/materials"
})
```

### 3.3 数据流关系

```cypher
// 数据流：从源系统到目标系统
(:ApplicationSystem {name: "SAP ERP"})-[:SENDS_DATA {
  flow_type: "ETL",
  frequency: "Daily"
}]->(:DataFlow {name: "物料数据同步"})-[:TO]->(:ApplicationSystem {name: "WMS系统"})

// 数据流：从源数据实体到目标数据实体
(:DataEntity {name: "物料主数据表", table_name: "MARA"})-[:FLOWS_TO {
  transformation: "数据清洗和转换"
}]->(:DataEntity {name: "WMS物料表", table_name: "WMS_MATERIALS"})
```

### 3.4 完整关系链

```cypher
// 业务流程 → 应用系统 → 数据实体 → 技术系统
(:BusinessProcess {name: "物料管理"})-[:SUPPORTED_BY]->(:ApplicationSystem {name: "SAP ERP"})
(:ApplicationSystem {name: "SAP ERP"})-[:MANAGES]->(:DataEntity {name: "物料主数据表"})
(:DataEntity {name: "物料主数据表"})-[:STORED_IN]->(:TechnologySystem {name: "Oracle-SAP-ERP", system_type: "DatabaseSystem"})
```

## 🔍 五、查询场景

### 5.1 查询应用系统的数据架构

```cypher
// 查询：SAP ERP的所有数据表
MATCH (app:ApplicationSystem {name: "SAP ERP"})
MATCH (app)-[:MANAGES]->(entity:DataEntity {entity_type: "Table"})
MATCH (entity)-[:STORED_IN]->(db:TechnologySystem {system_type: "DatabaseSystem"})
RETURN 
  app.name as application,
  entity.name as table_name,
  entity.table_name as physical_table,
  entity.meta_data.schema as schema,
  db.name as database
ORDER BY entity.table_name
```

### 5.2 查询API接口及其数据依赖

```cypher
// 查询：SAP ERP的所有API接口及其数据依赖
MATCH (app:ApplicationSystem {name: "SAP ERP"})
MATCH (app)-[:PROVIDES]->(api:APIInterface)
OPTIONAL MATCH (api)-[:QUERIES]->(entity:DataEntity)
RETURN 
  app.name as application,
  api.name as api_name,
  api.endpoint as endpoint,
  api.method as method,
  collect(DISTINCT entity.name) as data_entities
ORDER BY api.name
```

### 5.3 查询系统间数据流

```cypher
// 查询：从SAP ERP到其他系统的数据流
MATCH (source:ApplicationSystem {name: "SAP ERP"})
MATCH (source)-[:SENDS_DATA]->(flow:DataFlow)-[:TO]->(target:ApplicationSystem)
OPTIONAL MATCH (flow)-[:FROM_ENTITY]->(source_entity:DataEntity)
OPTIONAL MATCH (flow)-[:TO_ENTITY]->(target_entity:DataEntity)
RETURN 
  source.name as source_system,
  target.name as target_system,
  flow.name as flow_name,
  flow.flow_type as flow_type,
  flow.frequency as frequency,
  source_entity.name as source_entity,
  target_entity.name as target_entity
ORDER BY target.name, flow.name
```

### 5.4 查询数据实体的完整关系链

```cypher
// 查询：物料主数据表的完整关系链
MATCH (entity:DataEntity {name: "物料主数据表", table_name: "MARA"})
OPTIONAL MATCH (entity)-[:BELONGS_TO]->(app:ApplicationSystem)
OPTIONAL MATCH (entity)-[:STORED_IN]->(db:TechnologySystem)
OPTIONAL MATCH (app)-[:SUPPORTED_BY]-(proc:BusinessProcess)
OPTIONAL MATCH (api:APIInterface)-[:QUERIES]->(entity)
RETURN 
  entity.name as entity_name,
  entity.table_name as table_name,
  app.name as application,
  db.name as database,
  collect(DISTINCT proc.name) as business_processes,
  collect(DISTINCT api.name) as api_interfaces
```

## 📊 六、数据架构层在架构中的位置

### 6.1 完整的五层架构

```
业务层 (Business Layer)
  ↓ USES / PRODUCES / CONSUMES
数据架构层 (Data Architecture Layer) ⭐
  ├─ 数据实体 (Data Entity): 数据表、视图
  ├─ 数据模型 (Data Model): 逻辑模型、物理模型
  ├─ 数据流 (Data Flow): 系统间数据流
  └─ API接口 (API Interface): REST、SOAP等
  ↓ BELONGS_TO / STORED_IN / PROVIDED_BY
应用层 (Application Layer)
  ├─ 核心系统: SAP ERP, MES, PLM
  ├─ 外围系统: WMS, CRM, SRM, 财务共享
  └─ 自建系统: 企业内部开发
  ↓ RUNS_ON / DEPENDS_ON
技术架构层 (Technology Architecture Layer)
  ├─ 数据库系统: Oracle, SQL Server, MySQL等
  ├─ 中间件系统: Redis, ESB, 消息队列
  └─ 基础设施系统: Docker, K8s, 云平台
```

### 6.2 关系链示例

```cypher
// 完整关系链：业务流程 → 应用系统 → 数据实体 → 技术系统
(:BusinessProcess {name: "物料管理"})
  -[:SUPPORTED_BY]->
(:ApplicationSystem {name: "SAP ERP"})
  -[:MANAGES]->
(:DataEntity {name: "物料主数据表", table_name: "MARA"})
  -[:STORED_IN]->
(:TechnologySystem {name: "Oracle-SAP-ERP", system_type: "DatabaseSystem"})
```

## ✅ 七、总结

### 7.1 数据架构层包含内容

```yaml
数据架构层:
  1. 数据实体 (Data Entity)
     - 业务数据实体
     - 数据库表
     - 数据视图
  
  2. 数据模型 (Data Model)
     - 逻辑数据模型
     - 物理数据模型
  
  3. 数据流 (Data Flow)
     - 系统间数据流
     - 数据集成
     - 数据同步
  
  4. API接口 (API Interface)
     - REST API
     - SOAP API
     - 其他接口
```

### 7.2 关键关系

```yaml
关系类型:
  1. 数据实体 → 技术系统: STORED_IN
     - 数据表存储在哪个数据库上
  
  2. 数据实体 → 应用系统: BELONGS_TO / MANAGES
     - 数据表属于哪个应用系统
  
  3. API接口 → 应用系统: PROVIDES / CALLS
     - 接口由哪个系统提供/调用
  
  4. API接口 → 数据实体: QUERIES
     - 接口查询哪些数据表
  
  5. 数据流 → 应用系统: SENDS_DATA / TO
     - 系统间数据流
```

### 7.3 建模建议

```yaml
建议:
  1. 数据实体按表建模
     - 每个数据库表是一个数据实体
     - 通过table_name字段存储物理表名
     - 通过technology_system_id关联到数据库实例
  
  2. API接口按端点建模
     - 每个API端点是一个接口
     - 通过endpoint字段存储接口地址
     - 通过application_system_id关联到应用系统
  
  3. 数据流按系统间数据流建模
     - 每个系统间数据流是一个数据流实体
     - 通过source_system_id和target_system_id关联系统
     - 通过source_entity_id和target_entity_id关联数据实体
```
